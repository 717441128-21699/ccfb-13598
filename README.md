# 睡眠呼吸暂停手机录音初筛系统

家用手机整夜录音 → 后端 FastAPI + numpy 信号处理 → 医生端网页查看整夜能量、
鼾声分布、体位统计、AHI 估算和憋气最长十段试听。用于多导睡眠监测（PSG）排床
之前的**初筛**，把重度睡眠呼吸暂停病人优先排上监测仪。

## 临床判据与输出

* **AHI（呼吸暂停低通气指数）**：每小时检出的呼吸暂停事件数。
  * `<5` 无 / `5–15` 轻度 / `15–30` 中度 / `>=30` 重度（与 PSG 分级一致）。
* 一次呼吸暂停 = 病人两次鼾声/呼吸之间，超过 10 秒且显著长于其本人典型呼吸
  周期（≥2.5 倍中位间隔）的安静气流中断，并优先要求一次**憋醒后的爆发性喘气**
  （gasp）确认；无喘气时仅在窗口极度安静时回退判定，并单独标注。
* 输出：AHI、严重程度、置信度、逐秒声音能量与鼾声标记、分小时统计、分体位
  统计、憋气最长的 10 段 WAV 切片（可在线试听）。

## 关键工程设计

| 需求 | 实现 |
| --- | --- |
| 仅用 numpy，不用 scipy/sklearn | 自写 WAV 读写、线性插值重采样、向量化 FFT 特征、球形 k-means |
| 8 小时 10 分钟内出结果 | 分块流式（5 分钟/块）处理，只保留逐帧描述符和少量事件模板，频谱矩阵用完即弃；实测实时倍率 500× 以上 |
| 同屋打呼/电视/空调不计到病人 | ① 稳态噪声（空调）靠帧级稳定性+低频+绝对能量门限识别；② 说话人靠白化频谱+响度+质心复合向量聚类，近麦克风（更响、更低频、有呼吸节律）的判为病人；③ 暂停窗用窗口自身的离散度判安静，恒定空调声不会被当成呼吸中断 |
| 憋气后喘气识别 | 短、中频、陡升的爆发事件，在恢复窗内强制回收给病人簇 |

### 模块结构

```
app/
  config.py       全部可调阈值（集中管理，便于临床标定）
  wavio.py        WAV 解析/分块读取/线性重采样/写出（支持 8/16/24/32-bit PCM）
  features.py     25ms 帧、10ms 跳；dBFS、过零率、质心、平坦度、低/中频占比
  detection.py    VAD、空调检测、鼾声补丁、喘气候选、k-means、病人簇选择
  apnea.py        呼吸暂停判定、喘气确认、AHI 与分级
  pipeline.py     流式编排、两遍模板提取、统计、憋气切片导出
  storage.py      SQLite 任务表
  main.py         FastAPI（上传/轮询/结果/切片/静态网页）
  synth/          仅用 numpy 的合成录音与七种场景（测试夹具）
web/index.html    医生工作台（原生 JS + Canvas，无外部 CDN，可内网部署）
tests/            39 个 pytest 用例 + 1 个可选 8 小时全夜测试
```

## 快速开始

```powershell
py -m pip install -r requirements.txt

# 跑全部测试（约 4-5 分钟，含合成录音）
py -m pytest tests/ -q

# 可选：真实 8 小时全夜端到端（合成 + 分析，约 3-4 分钟）
$env:RUN_FULL_8H='1'; py -m pytest tests/test_performance.py::test_full_eight_hour_night -s

# 生成一条合成录音
py -m app.synth.generate --scenario severe --minutes 60 --out data/samples

# 启动服务
py -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 浏览器打开 http://127.0.0.1:8000
```

上传 WAV 时可附带一个体位 JSON（来自手机加速度计），格式：

```json
{"positions": [
  {"start": 0, "end": 14400, "position": "supine"},
  {"start": 14400, "end": 21600, "position": "left"},
  {"start": 21600, "end": 28800, "position": "right"}]}
```

## 合成测试场景（验收用，全部 numpy 生成）

`normal / mild / moderate / severe / roommate / ac_tv / mixed`，每个场景带机器
可读 ground truth（真实暂停时刻、病人/同屋鼾声、空调与电视区间、体位）。合成器
建模独立共振峰的多个说话人、节律性鼾声、10–35 秒暂停后的爆发喘气、稳态空调 hum、
不规则电视语音和棕色房间底噪。

## 已知能力边界（诚实声明）

1. **单声道 + 两个说话人节律/电平高度重叠**（`mixed` 极限场景）：当空调把病人
   鼾声压到与床另一侧同屋仅差 ~2 dB 时，单麦克风物理上难以完全分离，系统会给
   低置信度提示而不是强行下重度结论。真实场景中手机在病人床头柜，电平差通常
   ≥10 dB，此时分离可靠（见 `roommate` 场景测试）。
2. 系统只建模**阻塞型呼吸暂停**（鼾声节律 + 气流中断 + 喘气），不识别中枢型
   暂停（无呼吸努力但也无鼾声，手机声学上不可见），后者必须靠 PSG 的胸腹带。
3. 低通气（hypopnea，呼吸变浅但未完全停止）未单独计数，AHI 偏向呼吸暂停指数
   AI；这是手机单通道声学方案的固有约束。
4. 所有阈值集中在 `app/config.py`，正式临床使用前需要用真实 PSG 配对数据重新
   标定，当前数值仅在合成数据集上验证。
